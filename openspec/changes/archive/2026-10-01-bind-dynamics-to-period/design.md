# Design

## Context

См. proposal.md — Why. Текущее состояние:

- `src/lib/analytics.ts` экспортирует `monthlyDynamics(transactions, months = 12)`,
  который строит ровно N последних месяцев относительно «сегодня», независимо от
  периода, выбранного на дашборде.
- `DashboardPage` вызывает `monthlyDynamics(data.transactions, 12)` и передаёт
  результат в `BarChart` (доходы/расходы) и `LineChart` (баланс).
- `PeriodSelect` уже вычисляет `PeriodState.range` (`{ from, to }`) для месяца,
  квартала, года и произвольного периода.
- `analytics.test.ts` содержит тест `monthlyDynamics`, проверяющий длину массива.

## Goals / Non-Goals

**Goals:**

- Графики динамики покрывают ровно выбранный период.
- Гранулярность адаптивная: ≤ 31 дня — по дням, иначе — по месяцам.
- Оба графика используют один массив точек (единый источник истины).

**Non-Goals:**

- Не менять библиотеку графиков и не трогать круговые диаграммы/итоги.
- Не добавлять сохранение периода в URL или стор.
- Не трогать бюджеты, повторяющиеся операции и другие модули аналитики.

## Decisions

- **Заменить `monthlyDynamics` на `dynamicsForRange(transactions, range)`**, а не
  добавлять вторую функцию рядом. Одна функция строит точки по произвольному
  диапазону; при длине > 31 дня её месячное поведение совпадает с прежним.
  Альтернатива (оставить `monthlyDynamics` и завести `dailyDynamics`) отвергнута:
  две ветки кода легко расходятся по формату подписей и сортировке.
- **Порог гранулярности — константа `DAY_GRANULARITY_MAX_DAYS = 31`.** Длина
  диапазона считается включительно: `dayjs(range.to).diff(dayjs(range.from), 'day') + 1`.
  31 выбран, чтобы месяц (28–31 день) всегда давал дневные точки, а квартал — месячные.
- **Формат подписей.** Дни — `D MMM` (например, «5 янв»); месяцы — `MMM YY`
  (как сейчас), чтобы не менять вид месячных графиков.
- **Единый массив для обоих графиков.** `BarChart` и `LineChart` получают один и
  тот же результат; заголовок линейного графика меняется с «Баланс по месяцам» на
  формулировку без привязки к месяцам (например, «Динамика баланса»).
- **Дашборд передаёт `period.range`** вместо `(data.transactions, 12)`.

## Risks / Trade-offs

- [Год при дневной гранулярности был бы ~365 точек] → порог 31 день гарантирует
  месячные точки для года; покрыто тестом на граничных периодах.
- [31 дневная точка может «зашумить» ось X на узком экране] → сохраняем текущий
  мелкий шрифт оси; при необходимости уменьшить число подписей через `interval`
  в `XAxis` (не меняет данные, только отображение).
- [Удаление `monthlyDynamics` ломает существующий тест] → тест переписывается под
  `dynamicsForRange` с проверкой длины и гранулярности для дневного и месячного случаев.
