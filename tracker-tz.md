# Техническое задание: трекер доходов и расходов

## 1. Общее описание

Веб-приложение (SPA) для учёта личных доходов и расходов. Работает полностью в браузере, без серверной части и авторизации. Данные хранятся локально на устройстве пользователя.

**Цель:** дать пользователю простой инструмент для фиксации операций, контроля бюджета и анализа динамики финансов.

## 2. Технологический стек

| Область | Решение |
|---|---|
| Язык | TypeScript |
| Фреймворк | React 18 |
| Сборка | Vite |
| UI-библиотека | MUI (Material UI) |
| Хранение данных | localStorage / IndexedDB |
| Графики | MUI X Charts (или Recharts) |
| Формы | React Hook Form + zod (валидация) |
| Даты | date-fns / dayjs |
| Локализация | Русский интерфейс, валюта ₽ по умолчанию |

Приложение — десктопный SPA; адаптив под мобильные не требуется (базовая резиновая вёрстка приветствуется, но не обязательна).

## 3. Модель данных

### 3.1. Транзакция (Transaction)
```
{
  id: string;                 // uuid
  type: 'income' | 'expense';
  amount: number;             // положительное число, в рублях
  categoryId: string;         // ссылка на категорию
  date: string;               // ISO-дата
  note?: string;              // комментарий
  tags: string[];             // теги
  isRecurring: boolean;       // создана ли повторяющейся операцией
  recurringId?: string;       // ссылка на шаблон повтора
  createdAt: string;
  updatedAt: string;
}
```

### 3.2. Категория (Category)
```
{
  id: string;
  name: string;
  type: 'income' | 'expense';
  color: string;              // для графиков
  icon?: string;
  isDefault: boolean;         // встроенная или пользовательская
}
```

### 3.3. Бюджет / лимит (Budget)
```
{
  id: string;
  categoryId: string;         // или null для общего лимита
  period: 'month' | 'week';
  limit: number;
  month?: string;             // 'YYYY-MM' — при необходимости лимита на конкретный месяц
}
```

### 3.4. Повторяющаяся операция (RecurringRule)
```
{
  id: string;
  type: 'income' | 'expense';
  amount: number;
  categoryId: string;
  note?: string;
  tags: string[];
  frequency: 'daily' | 'weekly' | 'monthly' | 'yearly';
  startDate: string;          // ISO
  endDate?: string;           // опционально
  lastGeneratedDate?: string; // служебное поле
}
```

### 3.5. Настройки (Settings)
```
{
  theme: 'light' | 'dark' | 'system';
  currency: 'RUB';
  startOfWeek: 1 | 0;
}
```

Хранение: объекты сериализуются в JSON. Базовая схема — отдельные ключи в localStorage; при росте объёма данных возможен переход на IndexedDB (интерфейс слоя хранения должен позволять замену).

## 4. Функциональные требования

### 4.1. Управление транзакциями (CRUD)
- Добавление дохода или расхода: сумма, категория, дата, комментарий, теги.
- Редактирование и удаление существующих операций.
- Валидация: сумма > 0, обязательные категория и дата.
- Список операций с сортировкой по дате и сумме.

### 4.2. Категории и теги
- Предустановленный набор категорий для доходов и расходов.
- Создание, переименование, удаление пользовательских категорий; выбор цвета и иконки.
- Защита: нельзя удалить категорию, к которой привязаны транзакции (предложить перенос).
- Теги — свободные метки, множественный выбор при создании операции, фильтрация по тегам.

### 4.3. Отчёты и графики
- Дашборд: текущий баланс, доходы/расходы за период, остаток.
- Динамика по месяцам (столбчатая или линейная диаграмма).
- Разбивка расходов и доходов по категориям (круговая/пончик-диаграмма).
- Выбор периода отчёта (текущий месяц, квартал, год, произвольный диапазон).

### 4.4. Бюджеты и лимиты
- Установка лимита на категорию и/или общий месячный лимит.
- Индикатор прогресса расхода лимита.
- Визуальное предупреждение при превышении лимита (цвет/бейдж).

### 4.5. Повторяющиеся операции
- Создание правил повтора (ежедневно/еженедельно/ежемесячно/ежегодно).
- Автогенерация пропущенных операций при открытии приложения.
- Управление правилами: пауза, редактирование, удаление.

### 4.6. Поиск и фильтры
- Поиск по комментарию и тегам.
- Фильтры: тип, категория, диапазон дат, диапазон суммы, теги.
- Комбинируемые фильтры, сброс фильтров.

### 4.7. Импорт / экспорт
- Экспорт всех данных в JSON (полный бэкап) и операций в CSV.
- Импорт из JSON с восстановлением данных; подтверждение перед перезаписью.
- Обработка ошибок формата файла.

### 4.8. Тёмная тема
- Переключение светлая/тёмная/системная через MUI ThemeProvider.
- Сохранение выбора в настройках.

## 5. Структура приложения

Рекомендуемая структура каталогов:
```
src/
├── app/                # точка входа, роутинг, провайдеры
├── components/         # переиспользуемые UI-компоненты
├── features/
│   ├── transactions/   # CRUD, список, формы
│   ├── categories/
│   ├── budgets/
│   ├── recurring/
│   ├── reports/        # дашборд, графики
│   └── settings/       # тема, импорт/экспорт
├── store/              # состояние (Context/Zustand/Redux)
├── lib/                # утилиты, форматирование, валидация
├── storage/            # слой доступа к localStorage/IndexedDB
├── models/             # типы TypeScript
└── theme/              # настройка MUI-темы
```

Маршруты (React Router):
- `/` — дашборд и отчёты
- `/transactions` — список операций, поиск и фильтры
- `/categories` — управление категориями
- `/budgets` — бюджеты и лимиты
- `/recurring` — повторяющиеся операции
- `/settings` — тема, импорт/экспорт

## 6. Управление состоянием

- Данные — централизованное хранилище (Zustand или Redux Toolkit — на выбор исполнителя) с синхронизацией в localStorage при изменениях.
- Рекомендуется отдельный «сервис»-слой, инкапсулирующий чтение/запись, чтобы упростить замену хранилища.

## 7. Нефункциональные требования

- **Производительность:** интерфейс отзывчив при 10 000+ операций (виртуализация списка при необходимости).
- **Надёжность:** устойчивость к повреждённым данным в localStorage (валидация при загрузке, безопасный фолбэк с пустым состоянием).
- **Валидация:** схема (zod) для импортируемых данных.
- **Качество кода:** strict-режим TypeScript, ESLint + Prettier, компонентная декомпозиция.
- **Доступность:** корректная работа с клавиатурой и ARIA на формах (требования MUI).
- **Данные:** всё хранится локально; приложение работает без сети после первой загрузки.

## 8. Границы MVP

**Входит:** всё из раздела 4.

**Не входит (на будущее):** авторизация, синхронизация между устройствами, серверная часть, мобильное приложение/PWA, мультивалютность, совместный доступ.

## 9. Этапы реализации (предложение)

1. Инициализация проекта (Vite + React + TS + MUI), тема, роутинг, каркас layout.
2. Модель данных и слой хранения (localStorage) с типами и валидацией.
3. CRUD транзакций + категории и теги.
4. Список операций: поиск, фильтры, сортировка.
5. Дашборд и графики.
6. Бюджеты и лимиты.
7. Повторяющиеся операции.
8. Импорт/экспорт, тёмная тема, настройки.
9. Полировка: тесты, проверка производительности, обработка edge-cases.

## 10. Критерии приёмки

- Можно создать, отредактировать и удалить доход/расход.
- Категории и теги управляются, фильтры и поиск работают.
- Дашборд корректно считает баланс и строит графики за выбранный период.
- Лимиты показывают прогресс и предупреждают о превышении.
- Повторяющиеся операции генерируются автоматически.
- Экспорт/импорт JSON и CSV сохраняет и восстанавливает данные.
- Тёмная тема работает и сохраняется между сессиями.
- Данные сохраняются между перезапусками браузера.
